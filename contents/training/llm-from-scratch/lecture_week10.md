## 0.4 이번 주 배경 지식 — 처음이라면

### 왜 모델이 매번 똑같은 말만 하는가

7주차에 만든 `generate_text_simple` 은 로짓에서 **가장 큰 것 하나**를 고릅니다.

```python
next_id = torch.argmax(logits, dim=-1)      # greedy — 항상 1등
```

**입력이 같으면 1등도 항상 같습니다.** 그래서 같은 프롬프트에 항상 같은 문장이 나옵니다.
ChatGPT 가 같은 질문에 매번 다르게 답하는 것과 대조적입니다.

**해결은 "1등을 뽑지 말고, 확률대로 추첨하기"** 입니다.

```python
probs   = torch.softmax(logits, dim=-1)      # 확률로 바꾸고
next_id = torch.multinomial(probs, num_samples=1)   # 확률대로 뽑는다
```

| 방식 | 동작 | 성격 |
|---|---|---|
| **greedy** (`argmax`) | 항상 1등 | 결정적. 재현 가능. 지루하고 반복적 |
| **sampling** (`multinomial`) | 확률에 비례해 추첨 | 다양함. 대신 이상한 말도 나옴 |

`multinomial` 은 **확률이 높으면 자주, 낮으면 가끔** 뽑습니다. 확률 0.6 인 토큰은 10번 중
6번쯤, 확률 0.01 인 토큰도 100번 중 1번쯤은 뽑힙니다.

> 📌 **이번 주는 그 "가끔"을 조절하는 손잡이 두 개를 답니다.** temperature 와 top-k 입니다.

### 엔트로피 — 분포가 얼마나 퍼져 있는가

이번 주 표에 계속 나오는 값입니다. **선택지가 얼마나 고르게 퍼져 있는지**를 숫자 하나로
나타냅니다.

| 분포 | 엔트로피 | 상태 |
|---|---|---|
| `[1.0, 0, 0, ...]` | **0** | 완전히 확신 |
| `[0.5, 0.5, 0, ...]` | 0.69 | 둘 중 하나 |
| 9개가 전부 1/9 | **2.20** | 완전히 무작위 |

**엔트로피가 0에 가까우면 지루하고, 최대에 가까우면 헛소리입니다.** 이번 주 실험에서
T=0.01 이면 0.0000, T=5.0 이면 1.9990 이 나옵니다 — 손잡이가 실제로 작동한다는 증거입니다.

### 체크포인트와 `state_dict`

훈련은 오래 걸립니다. 중간에 끊기면 처음부터 다시 하는 것은 낭비입니다. 그래서 **모델의
숫자들을 파일로 저장**해 둡니다.

```python
torch.save(model.state_dict(), "model.pth")     # 파라미터만 저장
model.load_state_dict(torch.load("model.pth"))  # 다시 불러오기
```

`state_dict` 는 **"파라미터 이름 → 텐서"** 딕셔너리입니다. 구조가 아니라 **숫자만** 들어
있습니다. 그래서 불러오려면 **같은 구조의 모델을 먼저 만들어 놔야** 합니다.

> 🔴 **이어서 훈련하려면 모델만으로는 부족합니다.** AdamW 가 파라미터마다 들고 있는
> 관성 상태 2개(9주차의 그 상태들)도 같이 저장해야 합니다. 안 그러면 재개 직후 손실이
> 튑니다. 미션 3에서 이걸 직접 확인합니다.

### 가중치 이식이 왜 어려운가 — 규약이 다르다

미션 5에서 OpenAI 가 훈련한 GPT-2 의 숫자를 **여러분이 만든 클래스**에 부어 넣습니다.
숫자 크기는 같은데 **정리 방식이 다릅니다.** 두 군데가 걸립니다.

**① QKV 가 한 텐서에 붙어 있다.**

```
OpenAI:  h.0.attn.c_attn.weight   shape (768, 2304)    ← 768 × 3
우리:    W_query, W_key, W_value  각각 (768, 768)
```

`torch.chunk(tensor, 3, dim=-1)` 로 **3등분**해야 합니다.

**② 행렬의 행/열이 뒤집혀 있다.**

TensorFlow 계열 규약은 `(입력, 출력)` 순서로 저장하고, PyTorch `nn.Linear` 는
`(출력, 입력)` 순서로 씁니다. 그래서 **전치(`.T`)** 가 필요합니다.

```python
linear.weight = nn.Parameter(loaded_tensor.T)     # 전치를 빼먹으면 shape 오류
```

> 💡 **shape 가 안 맞으면 오류라도 납니다. 더 무서운 건 "우연히 맞는" 경우입니다.**
> 768×768 정사각 행렬은 전치해도 shape 가 같아서 **오류 없이 틀린 값이 들어갑니다.**
> 그래서 이번 주 프롬프트에는 `assign()` 함수로 shape 를 명시적으로 검사하고,
> **로드 후 생성 품질까지** 확인하라고 되어 있습니다.

### 왜 남의 가중치를 가져오는가

9주차에 훈련한 모델은 단편소설 하나(5,145 토큰)만 봤습니다. 유창할 리가 없습니다.
OpenAI 는 같은 구조를 **수백억 토큰**으로 훈련했습니다.

| 모델 | 훈련 데이터 | val 손실 |
|---|---|---|
| 우리 것 (W09) | 5,145 토큰 | 6.31 |
| **OpenAI 124M** | 수백억 토큰 | **3.56** |
| **OpenAI 355M** | 같은 데이터, 큰 모델 | **3.36** |

**구조는 우리 것과 같습니다.** 다른 것은 숫자뿐입니다. 이번 주 이후 11~13주차는 전부
이 이식된 모델 위에서 진행합니다.

## 0.5 신입생을 위한 핵심 개념

### temperature 는 로짓을 나누는 것뿐이다

```python
probs = torch.softmax(logits / temperature, dim=-1)
```

**그게 전부입니다.** 그런데 효과는 극적입니다.

| T | 효과 | 비유 |
|---|------|------|
| **작다** (0.1) | 로짓 차이가 **커져** 최고값에 확률이 몰림 | 확신에 찬 사람 |
| **1.0** | 원래 분포 그대로 | 평소 |
| **크다** (5.0) | 로짓 차이가 **작아져** 평평해짐 | 아무 말이나 |

장난감 어휘 9개로 실측하면:

| T | `forward` 선택 (1000회 중) | `pizza` 선택 | 엔트로피 |
|---|---|---|---|
| 0.01 | **1000** | 0 | 0.0000 |
| 0.1 | 995 | 0 | 0.0514 |
| 1.0 | 576 | 0 | 0.9127 |
| **5.0** | 237 | **41 (약 4%)** | **1.9990** |

`pizza` 는 로짓이 **−1.89** 로 최하위권입니다. T=1 에서는 사실상 **0회** 뽑히지만, T=5 에서는
**약 4%** 나 뽑힙니다. **temperature 를 올린다는 것은 "말도 안 되는 후보에게도 기회를 준다"는
뜻입니다.**

### top-k 는 `-inf` 트릭의 재등장

```mermaid
graph TD
    L["로짓 9개<br/>[4.51, 0.89, -1.90, 6.75, 1.63, -1.62, -1.89, 6.28, 1.79]"] --> T["torch.topk(logits, 3)<br/>상위 3개: 6.75, 6.28, 4.51"]
    T --> M["나머지를 -inf 로<br/>masked_fill / torch.where"]
    M --> S["softmax<br/>→ 나머지가 정확히 0"]
    S --> P["확률 3개, 합 = 1.0"]
    style M fill:#d29922,color:#fff
    style S fill:#3fb950,color:#fff
```

**5주차 인과 마스크와 정확히 같은 트릭입니다.** 0으로 만들면 `e⁰ = 1` 이라 남지만,
`-inf` 로 만들면 `e^(-inf) = 0` 이라 사라집니다. 이 수업에서 세 번째로 나오는 패턴입니다.

> ⚠️ **top-k 와 temperature 를 함께 쓸 때 순서:** 먼저 top-k 마스킹, 그다음 temperature 나눗셈,
> 그다음 softmax 입니다. 순서를 바꾸면 `-inf / T` 가 되어(여전히 `-inf` 라 결과는 같지만)
> 의도가 흐려집니다.

## 2. 미션 3 — generate 통합과 (T × k) 그리드

**📋 실행 프롬프트 P10-3** (요지)

```text
[목표] temperature·top-k·eos 를 지원하는 generate 구현
[할 일] week10/decoding.py 에:
 generate(model, idx, max_new_tokens, context_size, temperature=0.0, top_k=None, eos_id=None)
 - top_k 가 주어지면 먼저 -inf 마스킹
 - temperature > 0 이면 softmax 후 multinomial, 아니면 argmax(greedy 폴백)
 - eos_id 가 나오면 조기 종료
[검증] (T, k) 그리드로 생성문을 표로 만들어 sampling_grid.md 에 저장
```

**핵심 구조:**

```python
if top_k is not None:
    logits = topk_mask(logits, top_k)
if temperature > 0.0:
    probs = torch.softmax(logits / temperature, dim=-1)
    idx_next = torch.multinomial(probs, num_samples=1)
else:
    idx_next = torch.argmax(logits, dim=-1, keepdim=True)   # greedy 폴백
```

**예상 결과:** 낮은 T·작은 k → 9주차에서 외운 문장으로 수렴 / 높은 T·큰 k → 문장 붕괴.

> ⚠️ **T=0.5 행에서 top_k 를 바꿔도 출력이 같을 수 있습니다 — 정상입니다.**
> 온도가 낮으면 확률이 최상위 몇 개에 몰려서, k를 5로 하든 25로 하든 뽑히는 토큰이 같아집니다.
> **버그로 오인하지 마세요.** k가 의미를 갖는 것은 분포가 평평할 때(높은 T)입니다.

**통과 기준:** pytest `3 passed` (greedy 폴백이 `generate_text_simple` 과 동일 / 시드 고정 시
재현 / top-k 제약이 지켜짐).

> | 누군가 변환해 둔 `.pth` | 🔴 **미션이 무력화된다** — `load_state_dict()` 한 줄로 끝나서 chunk 분할도 전치도 배우지 못한다 |
>
> **`.pth` 지름길을 쓰면 이 미션의 학습 목표가 통째로 사라집니다.** 실제로 확인해 봤습니다 —
> 702MB `.pth` 를 받아 `load_state_dict(..., strict=True)` 를 돌리니 **한 줄로 성공**했습니다.
> 그래서 이 실습은 **safetensors 를 필수로 지정**합니다.

### 4.1 두 가지 변환 — chunk 분할과 전치

**(b) 전치는 4주차 연습문제 3.1 그 자체입니다.** 그때 "v2 → v1 이식에 왜 `.T` 가 필요한가"를
설명하게 만든 이유가 여기 있습니다. **6주 전의 연습이 오늘 회수됩니다.**

### 4.2 `qkv_bias=True` 가 필수인 이유

**✅ 검증 프롬프트 V10-3** 은 일부러 `qkv_bias=False` 로 로드를 시도하게 합니다.

```
AttributeError: 'NoneType' object has no attribute 'shape'
```

**오류가 나는 것이 정답입니다.** OpenAI 의 GPT-2 에는 QKV bias 가 **있는데** 우리 모델에
그 자리가 없으니 넣을 데가 없습니다. 5주차에서 계산한 `2,360,064` vs `2,362,368` 의
**2,304 = 3 × 768** 차이가 바로 이것입니다.

| 모델 | the-verdict val 손실 | 퍼플렉시티 | 무엇이 다른가 |
|---|---|---|---|

| 내 10에폭 모델 | **6.31** | 551 | 5,145 토큰을 외움 |

> **모델을 키우는 것보다 데이터를 늘리는 것이 압도적으로 효과적**이라는 사실이 이 표에 있습니다.

## 5. 에이전트에게 시키는 법 — 이번 주 실전

### 5.1 이번 주의 새 개념 — "게이트"를 프롬프트에 심는다

가중치 이식은 **조용히 틀리기 좋은 작업**입니다. shape 가 우연히 맞으면 오류 없이 엉뚱한
숫자가 들어가고, 생성 결과를 봐야만 알 수 있습니다. 그래서 프롬프트에 **중간 검문소**를
넣습니다.

```text
[할 일]
 3. assign(left, right): shape 불일치면 즉시 ValueError 를 던질 것
[검증] shape 불일치가 나면 어느 키에서 났는지 함께 보고할 것
```

| 게이트 | 잡아내는 것 |
|---|---|
| `assign()` 의 shape 검사 | 크기가 다른 텐서를 넣는 실수 |
| 로드 후 **생성 품질** 확인 | shape 는 맞는데 전치를 빼먹은 경우 |
| val 손실 **3.56** 대조 | 위 둘을 다 통과했는데도 미묘하게 틀린 경우 |

**셋을 다 통과해야 이식이 성공한 것입니다.** 하나만으로는 부족합니다.

> 📌 **이것이 "게이트 설계"입니다.** 에이전트가 만든 결과를 사람이 한 줄씩 읽을 수 없을 때,
> **통과해야만 넘어갈 수 있는 관문**을 여러 겹 두는 것. 13주차 LoRA 의 "B=0 항등 게이트",
> 14주차 KV 캐시의 "출력 완전 동일성 게이트"가 전부 같은 사상입니다.

### 5.2 지름길을 막는 프롬프트

인터넷에는 누군가 변환해 둔 `.pth` 파일이 있습니다. 그걸 쓰면 `load_state_dict()` 한 줄로
끝납니다. **그리고 이번 주 학습 목표가 통째로 사라집니다.**

**긴 길을 명시적으로 지정**해야 합니다.

> 🔴 **실제로 확인했습니다.** 702MB `.pth` 를 받아 `load_state_dict(..., strict=True)` 를

## 실습 안내

이번 주 실습(`lab_week10.yaml`, 7단계)은 llm-lab 컨테이너에서 진행합니다. 5단계 이후는 GPU 와
네트워크(가중치 다운로드 548MB / 1520MB)를 씁니다.

### 1) 이 실습을 왜 하는가?

10주차에서 이식한 **OpenAI 355M 모델**이 11~13주차의 출발점입니다. 11주차 스팸 분류기도,
13주차 지시 튜닝도 전부 이 가중치 위에서 시작합니다. 그리고 디코딩 파라미터(T, k)는
LLM 서비스를 다룰 때 가장 자주 만지는 손잡이입니다.

### 2) 무엇을 알 수 있는가?

- temperature 가 **로짓을 나누는 한 줄**일 뿐이라는 것, 그리고 그 효과의 크기.
- `-inf` 트릭이 세 번째로 등장한다는 것(인과 마스크 → top-k).
- 남의 가중치를 내 클래스에 붓는 일이 **chunk 분할 + 전치** 두 가지라는 것.
- "차이는 데이터의 양"이라는 결론을 **한 표의 숫자**로 보는 것.

### 3) 결과 해석 (정상 vs 비정상)

| 확인 | 정상 | 비정상 → 의심할 곳 |
|------|------|-------------------|
| argmax 단어 | **forward** (6.75) | 다르면 어휘 인덱스 오류 |
| T=1 에서 pizza | 사실상 **0회** | 자주 나오면 T 적용 위치 확인 |
| T=5 에서 pizza | 약 **4%** | 0이면 temperature 나눗셈 누락 |
| 엔트로피 | T 증가에 **단조 증가** | 아니면 계산식 확인 |
| top-3 로짓 | **6.75 / 6.28 / 4.51** | 다르면 `topk` dim 확인 |
| 마스킹 후 확률 | 나머지 **정확히 0**, 합 **1.0** | 0이 아니면 **0 마스킹**을 한 것 |
| T=0.5 행 k 변화 | **출력이 같아도 정상** | 버그로 오인 금지 |
| 체크포인트 재개 | val 손실 **소수 3~4자리 일치** | 다르면 eval 모드/시드 확인 |
| `qkv_bias=False` 로드 | **오류가 정상** | 성공하면 bias 를 안 넣은 것 |
| OpenAI 124M val | **3점대 중반** (3.56) | 6점대면 이식 실패 |
| 355M val | **3.36** | 124M 보다 낮아야 함 |

### 4) 실전 활용

`temperature` 와 `top_k`(그리고 `top_p`)는 모든 LLM API 의 표준 파라미터입니다. "분석·채점에는
낮은 온도, 브레인스토밍에는 높은 온도"라는 실무 규칙의 근거가 이번 주 측정입니다.
그리고 가중치 포맷 변환(safetensors ↔ 프레임워크 규약)은 오픈 모델을 다룰 때 반드시 만나는 일입니다.

## 흔한 오해

- ❌ **"temperature 는 복잡한 알고리즘"** → `logits / T` 한 줄입니다.
- ❌ **"top-k 는 상위 k개의 확률을 그대로 쓴다"** → 나머지를 `-inf` 로 만든 뒤 **다시 softmax**
  하므로 확률이 재분배됩니다. 합이 1이 되는 이유입니다.
- ❌ **"T=0.5 에서 k를 바꿨는데 출력이 같으면 버그"** → **정상**입니다. 온도가 낮아 상위 몇 개에
  확률이 몰려서 k가 무의미해진 것입니다.
- ❌ **"모델만 저장하면 된다"** → 옵티마이저 모멘텀이 없으면 재개 시 손실이 튑니다.
- ❌ **"변환된 .pth 를 받으면 편하다"** → **미션이 무력화됩니다.** chunk 분할도 전치도 배우지
  못합니다.
- ❌ **"`qkv_bias` 는 사소한 옵션"** → `False` 면 OpenAI 가중치 로드가 **실패**합니다.
- ❌ **"355M 이 124M 보다 훨씬 좋을 것"** → 3.56 → 3.36 입니다. **데이터가 같으면 크기의
  효과는 제한적**입니다.
