# speed_report.md — 훈련 속도 실험 (P9-4 산출물)

환경: NVIDIA GB10 / torch 2.9.1+cu130 / 모델 GPT-2 124M (ctx 256)
측정 규약: GPU 측정은 워밍업 1회 후 시작, 시작·종료 시 `torch.cuda.synchronize()`. 각 실험 사이 모델·옵티마이저 재생성(시드 123 고정)

## 표 A — 장치 비교 (batch=2, 1 에폭, 3회 평균)

| 장치 | 1에폭 시간(s) | 3회 측정값 | CPU 대비 배속 |
|---|---|---|---|
| CPU | **13.60** | 13.64, 13.57, 13.59 | 1.00배 |
| GPU (fp32) | **1.18** | 1.18, 1.18, 1.18 | 11.50배 |
| GPU + bf16 autocast | **1.05** | 1.05, 1.04, 1.05 | 12.97배 |

- GPU(fp32) 는 CPU 대비 **11.5배**
- bf16 은 fp32 대비 **1.13배** — 이득이 크지 않다

## 표 B — GPU 처리량

| batch | 배치 수 | 시간(s) | tokens/sec | batch=2 대비 처리량 배율 |
|---|---|---|---|---|
| 2 | 9 | 1.184 | **3,892** | 1.00배 |
| 8 | 2 | 0.762 | **5,373** | 1.38배 |
| 32 | 0 | — | — | (샘플 부족) |

## 검증 — batch 를 키울 때 tokens/sec 는 어떻게 변하는가

batch 2 → 8 으로 키우면 tokens/sec 가 3,892 → 5,373 로 **1.38배** 뛴다.
반면 1에폭 시간은 1.184s → 0.762s 로 거의 변하지 않는다.

### 이 모델·데이터가 GPU 를 충분히 활용하고 있는가

**아니다.** 근거 세 가지.

1. batch=2 에서 batch=8 로 키워도 **1에폭 시간이 거의 그대로**인데
   처리량은 1.38배가 된다. 같은 시간에 더 많은 일을
   했다는 뜻이므로, batch=2 일 때 GPU 가 놀고 있었다는 직접 증거다.
2. bf16 의 이득이 1.13배에 그친다. 연산이 병목이면 bf16 이
   확실한 이득을 주는데, 그렇지 않다는 것은 병목이 연산이 아니라는 뜻이다
   (커널 실행 오버헤드·데이터 공급이 병목).
3. 데이터가 5,145 토큰뿐이라 batch=2 로는 1 에폭이 배치 9개로 끝난다.
   GPU 를 예열할 틈도 없이 에폭이 끝난다.

**결론: 작은 배치는 GPU 를 굶긴다.** 11~13주차의 큰 훈련에서는 배치를 먼저 키워
GPU 를 포화시킨 뒤 정밀도(bf16)를 논해야 한다.
