# resume_experiment.md — 체크포인트 저장·로드·이어 훈련 (P10-4 산출물)

모델: GPT-2 124M (ctx 256) / 데이터: the-verdict.txt / 옵티마이저: AdamW lr=4e-4, weight_decay=0.1

## 1. 핵심 3수치

| 항목 | train 손실 | val 손실 |
|---|---|---|
| 저장 직전 (5에폭 종료) | 4.0834 | **6.2453** |
| 로드 직후 (새 프로세스) | 4.0834 | **6.2453** |
| 차이 | 0.000000 | 0.000000 |

로드 직후 val 손실이 저장 직전 값과 **소수 4자리까지 일치**한다(True). 이것이 로드 성공의 판정 근거다 — 일치하지 않으면 state_dict 가 제대로 실리지 않았다는 뜻이다.

옵티마이저까지 실렸다는 별도 증거:

- `exp_avg`(1차 모멘트) 텐서 161개가 존재하고 L2 노름 평균이 0.018136 로 0 이 아니다
- 옵티마이저 `step` 카운터 = 90 (5에폭 × 9배치 = 45 스텝)

## 3. 5+5 이어 훈련 vs 9주차 연속 10에폭

| | train | val |
|---|---|---|
| 9주차 연속 10에폭 | 0.8908 | 6.3130 |
| 이번 5+5 이어 훈련 | 0.8394 | 6.3115 |

두 값이 완전히 같지는 않다. 셔플 순서(DataLoader 의 난수)와 이어 훈련 시점의 `torch.manual_seed(123)` 재설정 때문에 배치 순서가 달라지기 때문이다. 손실 수준이 같은 동네라는 것이 체크포인트가 제대로 작동했다는 증거다.
