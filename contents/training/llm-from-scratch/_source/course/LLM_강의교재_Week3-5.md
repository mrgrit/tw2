## 3.1 배경 이론

**LLM의 학습 문제는 단 하나다: "다음 토큰 맞히기".** 그래서 학습 데이터는 (입력 시퀀스, 정답 시퀀스) 쌍인데, 정답은 놀랍게도 **입력을 왼쪽으로 한 칸 민 것**이다. 입력이 `[40, 367, 2885, 1464]`라면 정답은 `[367, 2885, 1464, 1807]` — 각 위치에서 "그다음에 올 토큰"이 정답이기 때문이다. 별도의 라벨링이 필요 없다. 텍스트 자체가 라벨이다.

**슬라이딩 윈도우.** 긴 텍스트 위에 길이 `max_length`짜리 창을 놓고 `stride`만큼 밀며 샘플을 뜯어낸다. stride가 작으면 샘플 수는 늘지만 인접 샘플 간 중복이 커지고(같은 내용을 여러 번 학습 → 과적합 위험), stride가 크면 중복은 줄지만 샘플 수가 준다. 샘플 수 공식은 손계산 가능하다:

> 샘플 수 = ⌈(전체 토큰 수 − max_length) ÷ stride⌉

**임베딩 = 조회 테이블.** 토큰 ID는 그냥 번호표다. 신경망에 넣으려면 각 ID를 연속 벡터로 바꿔야 하는데, 그 변환표가 임베딩 행렬(어휘 크기 × 차원)이고 **행렬의 각 행이 곧 그 토큰의 벡터**다. 이 표의 값들은 처음엔 난수이고, 훈련 과정에서 학습된다. 수학적으로는 원-핫 벡터와 행렬의 곱과 동치이지만, 곱셈 대신 "행 조회"로 구현해 효율을 얻는다 — 이번 주에 이 동치성을 직접 증명한다.

**위치 임베딩.** 임베딩 조회만 하면 심각한 문제가 남는다: 같은 토큰은 문장 어디에 있든 같은 벡터가 된다. "개가 사람을 물었다"와 "사람이 개를 물었다"를 구분할 정보가 없다. 그래서 위치별 벡터(위치 임베딩)를 **더해** 순서 정보를 주입한다. GPT-2는 위치 임베딩도 학습한다(절대 위치 방식).

## 3.6 미션 4 — 실전 파이프라인 조립 (GPT-2 규모)

**무엇을, 왜:** 실제 GPT-2 어휘 크기(50,257)와 교재 실습 차원(256)으로 토큰 임베딩 + 위치 임베딩 파이프라인을 조립한다. 그리고 임베딩 행렬이 얼마나 큰 물건인지 파라미터 수를 **손계산**한다.

**📋 실행 프롬프트 P3-4**

```text
[목표] 배치 → 토큰 임베딩 → 위치 임베딩 합성까지 전체 파이프라인
[할 일] week03/embedding_pipeline.py 작성 후 실행:
 1. create_dataloader_v1로 batch_size=8, max_length=4, stride=4,
    shuffle=False 로더 생성, 첫 배치 획득
 2. 토큰 임베딩 층: vocab_size=50257, output_dim=256
 3. 위치 임베딩 층: context_length=4(=max_length), output_dim=256,
    입력은 torch.arange(max_length)
 4. input_embeddings = 토큰 임베딩 + 위치 임베딩
 5. 각 단계의 텐서 shape를 순서대로 출력: 배치 → 토큰 임베딩 →
    위치 임베딩 → 최종 합
 6. 토큰 임베딩 층과 위치 임베딩 층의 파라미터 개수를 각각 출력
[검증] 위치 임베딩(shape [4,256])이 [8,4,256] 텐서에 더해질 때 어떤 규칙
      (브로드캐스팅)이 적용되는지 한 문단으로 설명할 것
```

**예상 결과 (정답지):** shape 흐름 `[8,4]` → `[8,4,256]` → `[4,256]` → `[8,4,256]`. 파라미터: 토큰 임베딩 **12,865,792개**(= 50,257 × 256), 위치 임베딩 1,024개(= 4 × 256).

**결과 테스트 방법 (직접 손계산):** 50,257 × 256을 직접 계산해 출력과 대조하라. 아직 모델 본체는 시작도 안 했는데 임베딩만 1,286만 파라미터다 — 2주차 생각해볼 문제 4번("어휘를 500만으로 키우면?")의 답이 여기서 명확해진다.

## 3.7 미션 5 — 위치 임베딩은 정말 필요한가 (관찰 실험)

**무엇을, 왜:** "위치 임베딩이 순서를 구분해준다"를 말이 아니라 텐서로 확인한다.

**📋 실행 프롬프트 P3-5**

```text
[목표] 위치 임베딩 유무에 따른 표현 차이 관찰
[할 일]
 1. 같은 토큰 ID가 두 번 나오는 짧은 시퀀스를 만들 것
    ⚠️ 함정 주의. `"the cat and the dog"` 는 **중복 토큰이 하나도 없다.**
       GPT-2 BPE 는 선행 공백을 토큰 안에 넣으므로 문장 맨 앞의 `"the"`(464)와
       중간의 `" the"`(262)가 **서로 다른 토큰 ID** 다.
       → 반드시 `tokenizer.encode(...)` 결과를 먼저 출력해 실제로 같은 ID가
         두 번 나오는지 눈으로 확인한 뒤 진행할 것.
       중복이 생기는 문장 예: `"I saw the cat and the dog"` (` the` = 262 가 두 번)
 2. 위치 임베딩 없이: 두 'the' 위치의 임베딩 벡터가 동일한지 비교
 3. 위치 임베딩을 더한 후: 두 위치의 벡터가 달라졌는지 비교
 4. 각 비교는 torch.equal / 벡터 차이의 노름으로 수치화
[형식] 결과를 week03/pos_experiment.md 에 관찰 기록으로 정리
[검증] "위치 임베딩이 없다면 모델 입장에서 어떤 두 문장이 구분 불가능해지는가"
      예시 문장 쌍을 1개 만들어 제시할 것
```

## 4.1 배경 이론

**왜 어텐션인가.** 지난주 완성한 임베딩에는 결함이 있다: 토큰의 벡터가 **문맥과 무관하게 고정**된다. "은행에 갔다"의 '은행'과 "강 은행(둑)"의 '은행'이 같은 벡터다. 어텐션은 각 토큰이 **문장 안의 다른 토큰들을 얼마나 참고할지** 가중치를 계산해, 문맥이 반영된 새 벡터(문맥 벡터)를 만든다.

**단순 어텐션의 3단계.** 쿼리 토큰 x에 대해 ① 모든 토큰과의 **내적**으로 유사도 점수를 구하고 ② **softmax**로 합이 1인 가중치로 정규화한 뒤 ③ 그 가중치로 모든 토큰 벡터를 **가중합**한다. 이 3단계가 어텐션의 전부이고, 나머지는 전부 이 뼈대의 변주다.

**학습 가능한 가중치 W_q, W_k, W_v.** 단순 버전은 임베딩을 그대로 비교하므로 "무엇을 기준으로 주목할지"를 배울 수 없다. 그래서 세 개의 행렬을 도입해 각 토큰을 쿼리(질문)·키(색인)·값(내용물)의 세 역할로 투영한다. 점수는 쿼리·키 내적으로, 문맥 벡터는 값의 가중합으로 계산한다. 이 세 행렬이 훈련으로 학습되는 부분이다.

**√d 스케일링.** 벡터 차원 d가 커지면 내적 값의 분산이 d에 비례해 커지고, 큰 점수가 softmax에 들어가면 출력이 거의 원-핫(한 곳에 몰빵)이 된다. 그러면 기울기가 죽어 학습이 어려워진다. 점수를 √d로 나누는 한 줄이 이것을 막는다 — 이번 주 마지막 실험에서 직접 측정한다.

## 4.7 미션 5 — √d 스케일링은 왜 필요한가 (측정 실험)

**📋 실행 프롬프트 P4-6**

```text
[목표] 차원 증가가 내적과 softmax에 미치는 영향 측정
[할 일] 실험 스크립트를 작성·실행하고 결과를 week04/scaling_experiment.md 에 표로 저장:
 1. d ∈ {8, 64, 512} 각각에 대해: 표준정규 무작위 벡터 쌍 1000개의
    내적을 계산해 분산을 측정
 2. d=512에서 무작위 점수 벡터(길이 6) 하나를 만들어,
    스케일링 없이 softmax한 결과와 √d로 나눈 뒤 softmax한 결과를
    나란히 출력 (각 분포의 최댓값도 표시)
[형식] 표 1: d | 내적 분산 (이론값 d와 비교) / 표 2: 스케일링 유무 | 분포 | 최댓값
[검증] 분산 측정값이 이론값 d에 근접하는지 표에서 판정할 것
```

**예상 결과:** 내적 분산 ≈ d (8, 64, 512 근처). 스케일링 없는 d=512 softmax는 한 원소가 거의 1인 원-핫에 가깝고, 스케일링 후에는 분포가 완만해진다.

## 5.1 배경 이론

**왜 미래를 가리는가.** GPT는 왼쪽에서 오른쪽으로 생성한다. 생성 시점에는 미래 토큰이 존재하지 않으므로, **훈련 때도 각 위치가 자기 이전 토큰만 보도록** 강제해야 훈련과 생성이 같은 조건이 된다. 이것이 코잘(causal) 어텐션이다.

**−inf 트릭.** 미래 위치의 점수를 softmax **이전에** −∞로 바꾸면, e^(−∞) = 0이므로 softmax 결과에서 그 위치의 가중치가 정확히 0이 되고, 나머지 가중치는 자동으로 합이 1이 된다. 순진한 방법(softmax 후 미래를 0으로 만들고 다시 정규화)과 결과가 같지만 한 번에 끝난다 — 이번 주 첫 미션에서 두 방식의 동치를 증명한다.

**어텐션 드롭아웃.** 훈련 중 어텐션 가중치의 일부를 무작위로 0으로 만들어 특정 연결에 대한 과의존을 막는다. 중요한 디테일: 살아남은 값은 1/(1−p)배로 **커진다**(기댓값 보존). p=0.5면 살아남은 값이 2배가 된다. 평가 모드(eval)에서는 드롭아웃이 꺼진다.

**멀티헤드.** 어텐션을 여러 개 병렬로 두면 각 헤드가 서로 다른 관계(예: 문법적 관계, 인접성)에 주목하도록 분업할 수 있다. 구현은 두 가지: ① 독립된 어텐션 여러 개를 만들어 출력을 이어붙이는 **래퍼 방식**(이해용) ② 하나의 큰 투영을 만들고 텐서를 헤드 수만큼 쪼개 병렬 계산하는 **분할 방식**(실전용, GPT-2 방식). 두 방식의 파라미터 배치는 다르지만 계산 골격은 같다. 그리고 분할 방식에는 많은 사람이 잘못 알고 있는 성질이 하나 있다 — 미션 6에서 직접 발견하게 된다.

```text
 2. 각각의 전체 파라미터 수와 head_dim 기록
 3. GPU에서 [4, 1024, 768] 무작위 입력으로 forward 시간 측정:
    워밍업 3회 후 10회 평균, 측정 전후 torch.cuda.synchronize 호출
[형식] 표: num_heads | head_dim | 파라미터 수 | 평균 forward 시간(ms)
[검증] 파라미터 수 열에서 발견되는 사실을 명시적으로 짚을 것
```

**예상 결과:** 파라미터 수는 세 경우 **완전히 동일**하다(2,362,368개). 헤드를 나누는 것은 같은 크기의 투영 출력을 조각내 병렬로 보는 것이지, 투영을 늘리는 게 아니기 때문이다. head_dim만 768 → 192 → 64로 줄어든다.

**시간은 다르다 — 헤드가 많을수록 느려진다.** 참고 실측(GB10, [4, 1024, 768] 입력): 1헤드 **3.48ms** → 4헤드 **5.11ms** → 12헤드 **10.10ms**, 즉 **2.90배**다.

왜 그런가. 어텐션 점수 텐서 `attn_weights` 의 shape 는 `[B, num_heads, T, T]` 다. 헤드 수에 **정비례**해 커진다. context_length=1024 에서 12헤드면 `4 × 12 × 1024 × 1024` = 5,030만 개 원소이고, softmax 와 마스킹이 이 전부를 훑는다. 파라미터(가중치 행렬)는 그대로여도 **중간 활성값의 부피가 12배**가 되는 것이다.

> **여기서 배울 것:** "파라미터 수가 같다 = 비용이 같다"가 아니다. 9주차 메모리 해부에서 다시 만날 구분이다 — 모델 크기(파라미터)와 실행 비용(활성값·중간 텐서)은 별개의 축이다. 실측하지 않고 "비슷하겠지"라고 넘어가면 이 사실을 놓친다.

**해석 과제 (report.md에 본인이 직접 작성 — 에이전트 사용 금지):** 파라미터 수가 같은데도 GPT-2가 헤드를 12개로 나눈 이유는 무엇일까? "여러 관점"이라는 통설을 head_dim과 연결해 자기 언어로 3~5문장 서술하라. 그리고 위 시간 측정을 근거로 "그 대가는 무엇인가"를 한 문장 덧붙여라.
