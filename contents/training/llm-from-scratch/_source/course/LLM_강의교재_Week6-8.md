## 6.1 배경 이론

**층 정규화(LayerNorm).** 깊은 신경망은 층을 지날수록 값의 분포가 제멋대로 흘러 훈련이 불안정해진다. LayerNorm은 **각 토큰 벡터를 그 벡터 안에서** 평균 0, 분산 1로 정규화한 뒤, 학습 가능한 scale(곱)과 shift(더하기)로 표현력을 되돌려준다. 배치 정규화와 달리 배치 크기와 무관하게 동작하므로 배치 구성이 유동적인 LLM에 적합하다. 분모가 0이 되는 것을 막는 아주 작은 수 eps(1e-5)가 들어간다.

**GELU.** ReLU는 음수를 전부 0으로 자른다 — 원점에서 꺾이고, 음수 구간의 기울기가 완전히 죽는다. GELU는 그 부드러운 대안으로, 음수도 조금은 통과시키며 모든 지점에서 매끄럽게 미분된다. GPT-2는 tanh 근사식의 GELU를 쓴다. 이번 주에 직접 그려서 ReLU와 비교한다.

**FeedForward(FFN).** 각 토큰 벡터를 독립적으로 768 → 3072(4배 확장) → 768로 통과시키는 2층 신경망(사이에 GELU). 어텐션이 "토큰들 사이"를 섞는 부품이라면, FFN은 "토큰 하나 안에서" 표현을 넓혔다 압축하며 가공하는 부품이다. 놀랍게도 블록 파라미터의 대부분은 어텐션이 아니라 이 FFN에 있다 — 직접 세어보면 안다.

**잔차 연결(shortcut).** 층의 출력에 입력을 그대로 더하는 `x + layer(x)` 구조. 역전파 때 기울기가 층을 우회해 흐를 수 있는 "고속도로"를 만들어, 깊은 네트워크의 기울기 소실을 막는다. 말로만 듣던 이 효과를 이번 주에 **기울기 크기를 직접 측정**해 확인한다.

**조립 순서(pre-norm).** GPT-2 블록은 [LayerNorm → 어텐션 → 드롭아웃 → 잔차 덧셈] 그리고 [LayerNorm → FFN → 드롭아웃 → 잔차 덧셈] 순서다. 정규화를 부품 **앞에** 두는 pre-norm 배치가 훈련 안정성에 유리하다.

## 6.3 미션 1 — LayerNorm: 테스트 우선 지시의 첫 실전

**무엇을, 왜:** 이번 주부터 지시의 순서를 바꾼다. **구현을 시키기 전에 "통과 기준이 되는 테스트"를 먼저 만들게 한다.** 테스트가 곧 명세서가 되므로, 여러분의 요구가 모호했는지가 구현 전에 드러난다.

**📋 실행 프롬프트 P6-1**

```text
[목표] 교재 4.2절과 동일한 LayerNorm 클래스 구현 — 단, 테스트 우선으로 진행
[1단계 — 테스트 먼저]
 week06/test_layers.py 에 아직 존재하지 않는 LayerNorm(emb_dim)에 대한
 pytest 4개를 먼저 작성해서 나에게 보여줘. 구현은 아직 하지 마:
 1. test_ln_mean_zero — 출력의 마지막 차원 평균이 0에 근접
 2. test_ln_var_one — 출력의 마지막 차원 분산(unbiased=False)이 1에 근접
 3. test_ln_params — scale과 shift가 학습 파라미터로 존재하고 초기값이
    각각 1, 0
 4. test_ln_shape — 입출력 shape 동일
[2단계 — 내 승인 후 구현]
 내가 "테스트 승인"이라고 하면 week06/layers.py 에 LayerNorm을 구현하고
 (torch.nn.Module 상속, scale·shift는 nn.Parameter, eps=1e-5,
 정규화 후 scale * x + shift), pytest를 실행해 통과시켜라.
 통과 후 곧바로 torch.nn.LayerNorm(emb_dim, eps=1e-5)와 같은 입력으로
 torch.allclose 대조까지 해서 True를 보여줄 것.
[제약] 테스트를 약화시키는 수정 금지.
 반대로 "틀린 테스트에 구현을 맞추는 것"도 금지 —
 테스트가 사양과 어긋나 보이면 구현을 굽히지 말고 나에게 먼저 알려라.
```

**예상 결과:** 4개 테스트 통과. `torch.manual_seed(123)`의 (2, 5) 무작위 배치로 확인하면 정규화 후 평균이 −0.0000/0.0000 수준, 분산 1.0000. 그리고 `torch.nn.LayerNorm`과의 allclose가 `True`.

> ⚠️ **이 미션에서 가장 흔한 사고 — "green인데 틀린 구현".** 테스트를 먼저 쓰게 하면, 에이전트가
> "마지막 차원 평균"을 **배치 축 평균**으로 잘못 읽고 그 테스트를 만든 뒤, 2단계에서 **그 틀린
> 테스트를 통과하도록 구현을 굽히는** 일이 실제로 일어난다(교차 검증에서 관측된 실패다). 그러면
> pytest는 전부 green인데 LayerNorm이 아니라 BatchNorm 비슷한 물건이 나온다. 막는 법은 하나뿐이다 —
> **초록불을 믿지 말고 공식 구현과 대조하라.** 그래서 2단계에 allclose 대조를 넣어 두었다.

**결과 테스트 방법:** 자체 구현을 **공식 구현과 교차 검증**한다. 같은 수학이라면 PyTorch의 `nn.LayerNorm`과 같은 답을 내야 한다.

**✅ 검증 프롬프트 V6-1**

```text
내 LayerNorm과 torch.nn.LayerNorm(emb_dim, eps=1e-5)를 동일 입력으로
비교해줘. 공식 구현의 초기 가중치(weight=1, bias=0)와 내 초기값이 같으므로
출력이 torch.allclose여야 한다. 결과를 보고하고, 만약 다르면 분산 계산의
unbiased 설정부터 의심해서 원인을 추적해줘.
```

**통과 기준:** allclose `True`.

## 6.6 미션 4 — 잔차 연결: 기울기 소실을 측정하다

**무엇을, 왜:** 5층짜리 장난감 네트워크로 shortcut 유무에 따른 **각 층의 기울기 크기**를 측정한다. "잔차 연결이 기울기 소실을 막는다"는 문장이 수치가 되는 순간이다.

**📋 실행 프롬프트 P6-4**

```text
[목표] shortcut 유무에 따른 기울기 크기 비교 (교재 4.4절 실험 재현)
[할 일] 실험 스크립트 작성·실행:
 1. ExampleDeepNeuralNetwork: layer_sizes=[3,3,3,3,3,1], 각 층은
    Linear+GELU, use_shortcut 플래그로 x + layer(x) 적용 여부 결정
 2. torch.manual_seed(123), 입력 [[1., 0., -1.]], 타깃 [[0.]]
 3. use_shortcut=False로 생성 → 역전파 → 각 층 가중치 기울기의 절대 평균 출력
 4. torch.manual_seed(123) 재설정 후 use_shortcut=True로 동일 절차
 5. 결과를 week06/shortcut_experiment.md 에 표로 저장:
    층 | shortcut 없음 | shortcut 있음 | 배율
[검증] 첫 번째 층(layers.0)의 배율이 몇 배인지 명시할 것
```

**예상 결과:** shortcut 없음: 첫 층 기울기 절대 평균 약 0.0002 수준까지 붕괴(출력에서 멀수록 급감). shortcut 있음: 첫 층도 약 0.22 수준 유지 — **천 배 이상 차이**.

**해석 과제 (report.md에 본인이 직접 작성 — 에이전트 사용 금지):** 역전파는 연쇄법칙, 즉 층별 기울기의 **곱**이다. 곱셈 연쇄가 왜 소실을 만들고, `x + layer(x)`의 덧셈 경로가 왜 이를 우회시키는지 3~5문장으로 설명하라.

**프롬프트 해설:** `test_block_causal` — 5주차의 성질 테스트를 상위 부품에 다시 적용했다. **좋은 테스트는 조립 후에도 재사용된다.** 부품이 옳아도 조립이 성질을 깨뜨릴 수 있기 때문이다(예: 잔차 덧셈을 마스킹 앞뒤 어디에 두느냐 같은 실수).

## 7.1 배경 이론

**전체 조립도.** GPT 모델은 지금까지 만든 부품의 직렬 연결이다: 토큰 임베딩 + 위치 임베딩(3주차) → 드롭아웃 → TransformerBlock × 12(5~6주차) → 최종 LayerNorm → 출력 헤드. 출력 헤드는 768차원 벡터를 어휘 크기 50,257차원의 **로짓**(각 토큰이 다음에 올 점수)으로 바꾸는 Linear 층이다.

**weight tying.** 토큰 임베딩 행렬(50257×768)과 출력 헤드 행렬(768→50257)은 모양이 전치 관계로 같다. GPT-2 원본은 이 둘을 **하나의 행렬로 공유**해 파라미터를 아꼈다 — 그래서 이름이 "124M"이다. 교재 구현은 학습 유연성을 위해 둘을 분리하므로 실제 파라미터는 1억 6,300만 개다. 이번 주에 이 차이를 숫자로 정확히 확인한다.

**greedy 생성 루프.** ① 현재까지의 토큰을 모델에 넣어 로짓을 얻고 ② **마지막 위치**의 로짓만 취해 ③ 가장 점수 높은 토큰(argmax)을 뽑아 ④ 뒤에 붙이고 반복한다. 입력이 context_length를 넘으면 앞을 잘라낸다. "가장 그럴듯한 것만 고르는" 이 방식의 한계는 10주차(temperature, top-k)에서 다룬다.

> 이번 주는 미션이 아니라 시험이다. 이 장은 시험의 구조, 규칙, 채점 기준, 그리고 **에이전트를 활용한 복습 전략**을 담는다. 준비 프롬프트(P8-x)는 시험 전 주에 자유롭게 사용하라.

## 8.0 시험 개요

| 구분 | 형식 | 배점 | 시간 | 도구 |
|---|---|---|---|---|
| 이론 | 지필 (워크북 변형 + 서술) | 50% | 60분 | 도구 없음 |
| 실기 | 버그 삽입 코드 3개 디버깅 | 40% | 60분 | **Claude Code 허용** (웹 검색 금지) |
| 구술 | 자기 저장소 랜덤 파일 설명 | 10% | 1인 5분 | 도구 없음 |

- 범위: 2~7주차 (교재 2~4장 + 수업 실험 전체)
- 실기 채점의 절반은 "서술"이다 — 고치는 것은 에이전트가 해도, **왜 틀렸고 왜 이 수정이 옳은지는 여러분의 문장**으로 평가한다.

## 8.1 무엇을 평가하는가

이 시험은 두 질문에 답한다.

1. **에이전트 없이도 설명할 수 있는가** — 이론과 구술. 한 학기 내내 "읽기는 의무"라고 했던 이유가 여기서 드러난다.
2. **에이전트와 함께 진단할 수 있는가** — 실기. 5주차 함정 카드의 확장판이다. 좋은 프롬프트로 빠르게 분기 지점을 좁히는 학생과, "고쳐줘"만 반복하는 학생은 같은 도구를 들고도 전혀 다른 답안을 낸다.

## 8.2 이론 시험 — 범위 자가점검 체크리스트

시험 전에 아래 항목을 "책을 덮고" 설명할 수 있는지 점검하라. 설명이 막히는 항목이 여러분의 복습 대상이다.

**2~3주차 (데이터 파이프라인)**
- [ ] 단순 토크나이저가 OOV에서 실패하는 이유와 `<|unk|>`·`<|endoftext|>`의 역할
- [ ] BPE가 OOV를 원리적으로 없애는 방법, 어휘 50,257의 구성
- [ ] 한국어가 더 많은 토큰으로 쪼개지는 이유와 그 실무적 의미
- [ ] "정답 = 입력을 한 칸 민 것"인 이유 / stride·max_length가 샘플 수·중복에 미치는 영향 (공식 포함)
- [ ] 임베딩 = 조회 테이블 = 원-핫 행렬곱, 위치 임베딩이 필요한 이유

**4~5주차 (어텐션)**
- [ ] 어텐션 3단계(점수→softmax→가중합)를 수치 예로 재현
- [ ] Q/K/V의 역할 분담과 √d 스케일링이 필요한 이유(분산 관점)
- [ ] 코잘 마스크의 −inf 트릭 / "0 마스킹"이 오답인 이유(e⁰=1)
- [ ] 드롭아웃의 1/(1−p) 스케일링과 train/eval 차이
- [ ] 분할 방식 멀티헤드의 shape 흐름 / 헤드 수와 파라미터 수의 관계(통념 깨기)

**6~7주차 (블록과 모델)**
- [ ] LayerNorm의 정규화 대상(마지막 차원)과 scale·shift의 존재 이유
- [ ] GELU와 ReLU의 차이 / FFN이 어텐션보다 파라미터가 많다는 사실
- [ ] 잔차 연결이 기울기 소실을 막는 원리 (측정 결과 인용 가능하면 최상)
- [ ] 163,009,536의 분해표를 백지에 재구성 / "124M" 이름의 유래
- [ ] greedy 생성 루프의 4단계와 훈련 전 모델이 헛소리를 하는 이유

## 8.3 실기 시험 — 형식과 규칙

**형식:** 2~7주차 범위의 코드(데이터로더·어텐션·블록·GPT·생성)에 버그가 1개씩 심긴 파일 3개를 받는다. 각 파일에 대해 답안지에 다음을 작성한다.

1. **버그 위치** — 파일명과 줄 번호
2. **원인 서술** — 무엇이 왜 수학적/구조적으로 틀렸는가 (본인 문장, 4~6줄)
3. **수정** — 고친 코드 (에이전트 사용 가능)
4. **검증 증거** — 수정 전후를 구분하는 테스트·수치 (5주차 인과성 테스트, 4주차 정답지 수치, 7주차 분해표 등 학기 자산 활용 권장)

**규칙:** Claude Code 사용 가능, 시험 종료 시 `/export`한 세션 로그를 답안과 함께 제출한다(로그 미제출 시 실기 0점). 웹 검색·타인과의 소통 금지. 로그에서 "원인 서술을 통째로 생성시킨" 정황이 확인되면 해당 문항 0점 — 진단에 쓰는 것과 서술을 대필시키는 것은 다르다.

**채점 루브릭 (문항당 13~14점, 총 40점 환산):**

| 항목 | 배점 | 기준 |
|---|---|---|
| 위치 특정 | 4 | 정확한 라인. 근처만 짚으면 부분 점수 |
| 원인 서술 | 5 | 수학·구조와 연결된 본인의 설명. 증상 나열만으로는 절반 |
| 수정·검증 | 4 | 수정의 정당성을 증거(테스트/수치)로 입증 |

**시간 배분 팁:** 문항당 20분. 첫 10분은 **직접 정독**(5주차 함정 카드 1단계와 동일), 다음 10분에 에이전트로 차등 테스트·가설 검증. 처음부터 에이전트에게 던지면 로그는 길어지고 서술은 얕아진다 — 채점자는 그 차이를 로그에서 본다.

## 8.4 구술 시험

교수가 여러분의 저장소에서 파일 하나를 즉석 추첨한다. 5분간 진행되며 전형적 질문은:

1. 이 파일은 무엇을 하고, 어느 주차의 어떤 개념을 구현했는가?
2. (교수가 한 줄을 지목하며) 이 줄이 없으면 무슨 일이 생기는가?
3. 이 코드를 만들 때 에이전트에게 어떤 검증을 시켰고, 왜 그 검증을 골랐는가?

평가 기준은 "유창함"이 아니라 **소유권**이다 — 자기 저장소의 코드를 자기 것으로 말하는가.

## 8.7 교수·조교용 출제 메모

*학생 배포본에서는 이 절을 제거할 것.*

**실기 버그 은행 (난이도 순):**

| # | 대상 | 버그 | 노림수 |
|---|---|---|---|
| 1 | 데이터로더 | target을 한 칸이 아니라 두 칸 밀기 | 3주차 시프트 검증 습관 |
| 2 | 데이터로더 | range 끝을 len(ids)로 잡아 마지막 청크 초과 | 경계 조건 |
| 3 | 어텐션 | √d 스케일링 생략 | 4주차 실험과 연결 |
| 4 | 어텐션 | softmax dim=-2 | 행/열 방향 이해 |
| 5 | 코잘 | 마스크를 −inf 대신 0으로 채움 | 5주차 V5-1 그 자체 |
| 6 | 코잘 | tril/triu 뒤바꿈 (미래만 보는 모델) | 인과성 테스트 유도 |
| 7 | MHA | transpose 누락 후 reshape (조용히 값만 오염) | shape는 맞는데 값이 틀린 최고 난도 |
| 8 | 블록 | 잔차 덧셈 누락 (x = Dropout(FF(LN(x)))) | 6주차 기울기 실험 연결 |
| 9 | GPT | 위치 임베딩 덧셈 누락 | 3주차 pos 실험 연결 |
| 10 | 생성 | `torch.argmax(logits.flatten(1), dim=-1)` — 마지막 위치를 고르지 않고 **전체를 평탄화**해 argmax | 7주차 루프 이해 |

> ⚠️ **출제 시 주의 — 8번과 10번은 서술을 그대로 쓰면 버그가 되지 않는다.** (검증 실측 확인 사항)
>
> **#8 잔차 덧셈 누락**: 12층 중 **한 층에만** 심어야 한다. 전 층에 심으면 훈련 손실이 눈에 띄게 발산해 누구나 "뭔가 크게 잘못됐다"고 알아채지만 어느 층인지 특정하지 못한다. 반대로 한 층에만 심으면 손실이 미묘하게 나빠지고, 학생이 **층별 출력 노름을 찍어 비교하는** 6주차 기울기 실험 기법을 실제로 써야 찾을 수 있다. 출제 시 "12개 블록 중 하나에 심었다"를 문제에 명시하라 — 명시하지 않으면 탐색 공간이 너무 넓다.
>
> **#10 argmax 위치**: "마지막 위치가 아닌 전체에 적용"을 소박하게 구현한 `torch.argmax(logits, dim=-1)[:, -1:]` 는 **버그가 아니다.** 마지막 시점의 argmax 를 먼저 슬라이스하나 나중에 슬라이스하나 결과가 수학적으로 같기 때문이다(정답 구현과 출력이 완전히 일치한다). 진짜 버그가 되려면 **차원을 평탄화해** 시점 정보를 뭉개야 한다:
> ```python
> idx_next = torch.argmax(logits.flatten(1), dim=-1, keepdim=True)   # 버그
> ```
> 이러면 `[B, T, 50257]` 이 `[B, T*50257]` 로 평탄화되어 argmax 가 **50257을 넘는 값**(실측 233626)을 내고, 다음 스텝의 임베딩 조회에서 `IndexError: index out of range in self` 가 난다. 학생이 오류 메시지에서 "인덱스가 어휘 크기를 넘었다 → 그럼 argmax 가 무엇 위에서 돌았나"를 역추적하게 되는 것이 이 문항의 노림수다.

- 3문항 구성 권장: 쉬움(1~3) 1개 + 중간(4~6, 8~9) 1개 + 어려움(7, 10) 1개. 학기마다 조합 교체.
- 구술 추첨은 시험장에서 실제 난수로(공정성 시연 겸). 파일이 너무 짧으면 재추첨.
- 이론 문항 소스: 워크북 변형 60% + 각 주차 "생각해볼 문제" 변형 40%. 수치 재구성형(분해표 백지 작성 등) 1문항 이상 포함 권장.
