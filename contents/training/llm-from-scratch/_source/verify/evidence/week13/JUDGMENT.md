# 발견된 결함

## 결함 #14 — "temperature=0 이면 재실행해도 같은 점수" 가 사실이 아니다 (**중대**, 교재-수치오류)

**위치**: Week11-13 교재 13.5절 P13-3 예상 결과 / V13-1 통과 기준

**교재 서술**:
> temperature=0 고정 덕에 **재실행해도 같은 점수가 나와야 한다.**
> **통과 기준:** 상한 ≫ 하한, **결정성 성립.**

**실측 — 결정성은 성립하지 않는다**:

V13-1 3번(같은 항목·응답 5개 × 3회):
```
Rewrite the sentence using a simile.           [50, 50, 50] 동일
What type of cloud is typically associated w   [50, 50, 50] 동일
Name the author of 'Pride and Prejudice'.      [95, 95, 95] 동일
What is the periodic symbol for chlorine?      [50, 75, 75] **변동**
Correct the punctuation in the sentence.       [50, 50, 50] 동일
→ 결정성 **불성립**
```

110개 전체를 두 번 채점한 결과:
```
1차 평균 60.92 / 2차 평균 60.71
점수가 달라진 항목: 9 / 110 (8.2%)
  · idx  0: 75 → 50    · idx  3: 50 → 75    · idx  6: 20 → 4
  · idx 19: 44 → 20    · idx 35: 80 → 100   · idx 40: 95 → 75
  · idx 80:  9 → 92    · idx 89: 96 → 80
변동 폭: [25, 25, 16, 24, 20, 20, 83, 16, 50]   평균 31.0점
```

**원인 규명 — 무작위성이 아니다.** 세 가지 실험으로 좁혔다.

1. **같은 프롬프트 20회 연속 호출** → `{75: 20}`, 저지 응답 원문도 `'75'` 1종.
   호출 단위의 무작위성은 **없다.**
2. **선행 문맥 6종 × 3회** → 전체 18회 중 첫 호출만 50, 나머지 17회 모두 75.
3. **콜드(keep_alive=0) 5회 vs 워밍 5회** → 콜드 `{75:5}`, 워밍 `{75:1, 50:4}`.
   콜드/워밍 이분법으로도 설명되지 않는다.

즉 **서버 측 실행 상태(KV 캐시 슬롯·배치 분할)에 의존하는 성분**이 남아 있고,
`seed`·`temperature` 로는 제거되지 않는다. 샘플링의 무작위성이 아니라
부동소수 누적 순서의 차이이기 때문이다.

**왜 하필 그 항목들인가 — 저지 점수는 앵커값에 몰린다**:
```
50점: 30건(27.3%)  95점: 16건(14.5%)  75점: 15건(13.6%)  20점: 13건(11.8%)
고유 점수 값 15종 / 110건.  앵커값(0/50/75/95/100) 집중도 61.8%
```
저지는 연속적인 점수를 내지 않고 소수의 앵커값 중 하나를 고른다. 두 앵커
사이에서 로짓이 팽팽한 경계선 항목(예: 정답 `Cl` vs 모델 `C`)에서 미세한
수치 차이가 greedy 선택을 뒤집어 **50 ↔ 75 처럼 25점씩 튄다.**

**중요한 반전 — 평균은 안정적이다.** 개별 점수는 8.2% 가 평균 31점씩 흔들리지만
**평균은 60.92 → 60.71, 0.21점만 움직였다.** 개별 점수는 못 믿고 평균은 믿을 수 있다.

**권고 (교재 수정안)** — P13-3 예상 결과와 V13-1 통과 기준을 교체.

```text
**예상 결과:** 평균은 저지 모델에 따라 크게 달라진다(결함 #15 참조).
⚠️ temperature=0·seed 고정으로도 **개별 점수의 완전 재현은 보장되지 않는다.**
   Ollama(llama.cpp)는 KV 캐시 슬롯 재사용과 배치 분할이 요청 순서에 따라 달라져
   부동소수 누적 순서가 바뀐다. 저지 점수가 소수의 앵커값(0/50/75/95/100)에
   몰리는 성질과 겹치면, 두 앵커 사이의 경계선 항목이 25점씩 튄다.
   (참고 실측: 110개 재채점에서 9건(8.2%) 변동, 평균 변동 폭 31점, 최대 83점.
    그러나 **평균은 60.92 → 60.71 로 0.21점만 움직였다.**)
   → 결론: **개별 점수는 비교 대상이 아니다. 평균만 비교하라.**
      그리고 평균 차이가 1점 이내면 "같다"고 판정하라.

**V13-1 통과 기준:** 상한 ≫ 하한. **결정성은 참고 항목이다** — 5개 중 1~2개가
흔들려도 정상이며, 흔들린 항목이 두 앵커값 사이를 오가는지 확인하라.
흔들림이 앵커값을 넘어 무작위로 퍼진다면 그때는 저지·프롬프트를 의심하라.
```

13.10 트러블슈팅의 `| 재채점 시 점수 변동 | options의 seed/temperature 미고정 |` 행도
아래로 교체:
```
| 재채점 시 개별 점수 변동 | seed·temperature 를 고정해도 남는 서버 측 실행 경로 차이 | 정상이다. 평균을 비교하라. 평균까지 크게 흔들리면 그때 options 를 확인 |
```

## 결함 #15 — 저지 모델이 미지정인데 평균 점수를 정답지로 제시한다 (**중대**, 교재-프롬프트결함)

**위치**: Week11-13 교재 13.5절 P13-3 1번 + 예상 결과

**교재 서술**:
> 1. Ollama 서비스 동작 확인… 저지 모델은 **`<조교 공지 8B급 모델명>`** 사용
> **예상 결과:** 평균 **50점 안팎**(교재의 355M·2에폭 기준)

모델명은 플레이스홀더로 비워 두면서, 그 모델이 내는 **평균 점수는 정답지로 못 박았다.**
저지 점수의 절대값은 저지 모델에 전적으로 좌우되는 값이라 이 둘은 양립할 수 없다.

**실측**: `llama3.1:8b` (원서가 쓰는 llama3 계열) 로 채점한 평균이 **60.92점**이다.
교재의 50점보다 **10.92점(21.8%) 높다.** 파이프라인은 정상이다 —
V13-1 상한 검증이 93.0 으로 통과했고, 파싱 실패는 0건이며,
튜닝된 모델의 응답 품질도 육안으로 양호하다(상위 3개가 정답과 문자열 일치).

즉 **학생은 자기 실습이 잘못됐는지 아닌지를 판단할 수 없다.**
±1%p 재현 게이트를 둔 11주차와 대비된다 — 거기서는 모델·데이터·하이퍼파라미터가
모두 고정이라 게이트가 성립했다.

**권고 (교재 수정안)**:


## 보정 권고 #7 — LoRA 스케일 표기가 배경이론과 실행 프롬프트에서 다르다 (경미)

**위치**: Week11-13 교재 13.1절 vs 13.6절 P13-4 1번

| 위치 | 서술 |
|---|---|
| 13.1 배경이론 | 출력 = W·x + **(α/r)**·B·A·x |
| P13-4 1번 | forward = **alpha** * (x @ A @ B) |

r=16, α=16 이면 α/r = **1** 이고 α = **16** 이다 — **16배 차이**다.
r=8, α=16 이면 α/r = 2 vs α = 16 — 8배 차이.

원서 저장소 부록 E 구현이 `alpha * (...)` 이므로 P13-4 쪽이 실행 기준이며,
이번 실습도 그렇게 구현해 게이트를 통과했다. 배경이론의 (α/r) 은 LoRA 원논문의
표준 표기라 그 자체로 틀린 것은 아니지만, 같은 교재 안에서 두 정의가 충돌하면
학생이 어느 쪽으로 구현할지 알 수 없다. 특히 **13.9 생각해볼 문제 5번**이
"r=8과 r=16의 차이가 거의 안 보였다면 r을 더 줄여도 될까"를 묻는데,
α/r 방식이면 r 을 줄일 때 스케일이 자동으로 커지고 α 방식이면 그렇지 않아
답이 달라진다.

**권고**: 13.1 배경이론을 실행 기준에 맞춘다.
```text
LoRA는 원본 가중치 W를 얼려두고 곁가지 저랭크 행렬 두 개만 학습한다:
출력 = W·x + α·(x·A·B), A는 (d_in × r), B는 (r × d_out), r ≪ d.
(LoRA 원논문은 스케일을 α/r 로 쓰지만, 우리는 교재 저장소 부록 E 구현을 따라
 α 를 그대로 곱한다. r 을 바꿔도 스케일이 자동 보정되지 않는다는 뜻이므로,
 13.9 문제 5번에서 r 을 줄일 때 이 점을 고려하라.)
```

## 저지 한계 사례 (13.5절 학생 과제의 참고 자료)

하한 검증에서 **엉터리 문장에 95점**을 준 항목을 찾았다.

```
[95점] idx 9
  지시  : Classify the following numbers as prime or composite.
  입력  : ': 11, 14, 19.'
  정답  : Prime numbers: 11, 19 / Composite numbers: 14
  투입한 응답: 'The weather is nice today.'      ← 완전히 무관한 문장
  저지 원문: '95'
```

저지가 지시·정답·응답을 한 프롬프트에 넣고 읽다가 **응답 자리를 무시하고
정답을 채점해 버린** 것으로 보인다. 이 한 건이 하한 평균을 41.9 로 끌어올렸다
(나머지 9건은 0~50). **하한 검증을 평균만 보고 통과 처리하면 놓치는 사례다** —
개별 점수를 반드시 나열해 확인해야 한다.
