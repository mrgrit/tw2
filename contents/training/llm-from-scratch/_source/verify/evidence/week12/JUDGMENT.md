## V12-1 문자 단위 대조 방법

노트북 셀 출력을 사람이 옮겨 적으면 그 자체가 오차원이 된다. `ch07.ipynb` 를 JSON
파싱해 **저장된 출력 문자열을 그대로** 읽어 비교했다.

| 케이스 | input | 내 출력 | 교재 출력 | 일치 |
|---|---|---|---|---|
| `data[50]` | 있음 (`Ocassion`) | 248자 | 248자 | ✅ 문자 단위 |
| `data[999]` | 없음 | 216자 | 216자 | ✅ 문자 단위 |

두 케이스가 각각 `### Input:` 블록의 **존재 경로와 생략 경로**를 덮는다.

## collate 3단계 진화

| 단계 | targets | 이 단계가 추가한 것 |
|---|---|---|
| draft 1 | — | 배치 최장+1 패딩 후 마지막 토큰 제거 |
| draft 2 | `[1,2,3,4,50256]` / `[6,50256,50256,50256,50256]` / `[8,9,50256,50256,50256]` | 한 칸 민 targets |
| 최종 | `[1,2,3,4,50256]` / `[6,50256,-100,-100,-100]` / `[8,9,50256,-100,-100]` | 첫 50256 하나만 남기고 -100 |

1행에 -100 이 없는 이유까지 확인했다 — draft2 의 패딩 위치가 `[4]` 하나뿐이라
"두 번째부터"가 존재하지 않는다.

## -100 실증

```
2토큰 손실        : 1.1269280910
3토큰(-100) 손실  : 1.1269280910
차이              : 0.00e+00      torch.equal: True

(대조) 세 번째를 진짜 라벨로 두면 : 0.7935947776  ← 0.3333 만큼 다르다
```

대조군이 핵심이다. 두 값이 같은 것만으로는 "세 번째 토큰이 원래 없었다"와 구별되지
않는다. 진짜 라벨을 넣었을 때 값이 달라지므로, 세 번째 토큰은 **있는데 무시된** 것이다.
그리고 `reduction='mean'` 의 분모가 3 이 아니라 2 라는 뜻이기도 하다 — 분자에서만
빼고 분모가 3 이었다면 손실이 2/3 로 줄어 두 값이 달랐을 것이다.

## P12-5 품질 점검 결과

| 점검 항목 | 건수 |
|---|---|
| 완전 중복 쌍 (instruction+input) | **20 그룹 / 45건** |
| └ 그중 output 이 서로 다른 그룹 | **20 그룹 (전부)** |
| 근사 중복 (instruction 앞 50자 동일) | 113 그룹 / 285건 |
| 빈 output / 빈 instruction | 0 / 0 |
| output 토큰 3개 미만 | 18건 |
| output == instruction | 0건 |
| 1024 토큰 초과 | **0건** |

토큰 길이: 최소 40 · 중앙값 55 · 95% 72 · **최대 91** · 평균 56.4

**교재 예상("심각한 문제는 적을 것")은 형식적 결함에 대해서는 맞다.** 그러나
완전 중복 20그룹 전부에서 output 이 서로 다르다 — **응답 스타일 모순**이다.

| idx | instruction | output | 토큰 |
|---|---|---|---|
| 708 | Classify the following statement… | `Negative` | 2 |
| 1060 | (동일) | `The statement "My computer crashed" can be classified as negative.` | 13 |
| 29 | What is the past tense of 'draw'? | `The past tense of 'draw' is 'drew.'` | 12 |
| 1068 | (동일) | `drew.` | 3 |

지시 튜닝이 가르치는 것은 지식이 아니라 **"지시가 오면 이런 형식으로 응답한다"** 는
규약이다. 동일한 프롬프트에 6.5배 길이 차이의 정답을 주면 모델은
"짧게 답할지 길게 답할지"에 서로 상쇄되는 신호를 받는다. 1,100건 중 45건(4.1%)이다.

**13주차 반영 조치**: 완전 중복 20그룹에서 각 1건만 남긴다(더 완전한 문장 쪽으로 통일).
1,100 → 1,075건. 근사 중복 113그룹은 input 이 다른 정당한 변형이므로 제외하지 않는다.

## 보정 권고 #5 — P12-1 이 고정 서두를 "..." 로 생략한다 (경미)

**위치**: Week11-13 교재 12.3절 P12-1 1번

**교재 서술**:
> 1. format_input(entry): 고정 서두(**"Below is an instruction ..."**) +
>    "### Instruction:" 블록 + …

프롬프트가 주는 정보만으로는 서두 문자열을 **복원할 수 없다.** 실제 문자열은
`"Below is an instruction that describes a task. Write a response that appropriately
completes the request."` 인데, `...` 뒤가 잘려 있다.

이번 실행에서는 통과했다 — Alpaca 템플릿이 워낙 널리 알려져 있어 에이전트가
사전 지식으로 정확히 복원했기 때문이다. 그러나 **프롬프트가 유도한 것이 아니라
모델의 기억이 채운 것**이므로, 이 프롬프트가 "예상 결과를 유도하는가"라는
검증 기준에서는 취약하다. 모델이 바뀌면(예: 소형 오픈 모델) 재현되지 않을 수 있다.

V12-1 의 diff 가 안전망 역할을 하므로 최종 결과는 지켜지지만, 순서가 뒤바뀐 셈이다
— 먼저 틀리게 쓰고 나중에 고치는 구조다.

**권고**: P12-1 1번에 서두 전문을 그대로 싣는다.
```text
 1. format_input(entry): 아래 고정 서두 + "### Instruction:" 블록 +
    input이 비어 있지 않을 때만 "### Input:" 블록을 붙여 반환
    고정 서두(개행까지 그대로):
      Below is an instruction that describes a task. Write a response that
      appropriately completes the request.
    ⚠️ 이 문자열은 문자 단위 규약이다. 기억에 의존해 쓰지 말고 그대로 옮길 것.
```
(V12-1 의 diff 검증은 그대로 유지한다 — 개행 수 검증에는 여전히 필요하다.)

## 보정 권고 #6 — P12-5 예상 결과가 지나치게 안심시킨다 (경미)

**위치**: Week11-13 교재 12.7절 P12-5 예상 결과

**교재 서술**:
> 이 데이터셋은 교재용으로 정제된 편이라 **심각한 문제는 적을 것이다** —
> "문제가 없음을 확인하는 것"도 점검의 정당한 결과다.

실측하면 완전 중복이 **20그룹 45건** 나온다. 그리고 그 20그룹 **전부**에서
output 이 다르다. 형식적 결함(빈 값·초과 길이)은 0건이 맞지만, 지시 튜닝에서
가장 중요한 **응답 스타일의 일관성**은 깨져 있다.

예상 결과가 "문제가 적다"고 미리 말해 버리면, 에이전트는 중복 탐지를 돌리고도
"20건 발견, 심각하지 않음"으로 요약하고 넘어가기 쉽다. 실제로 이번 점검에서도
초안 리포트가 형식 결함 0건만 보고 "심각한 문제 없음"으로 결론지었다가,
중복 그룹의 output 을 열어 본 뒤에야 스타일 모순을 발견했다.

**권고**: 예상 결과를 아래로 교체.
```text
**예상 결과:** 형식적 결함(빈 output, 빈 instruction, 1024 토큰 초과)은 0건일
것이다 — 교재용으로 정제된 데이터셋이다. 하지만 **거기서 멈추지 마라.**
완전 중복 쌍을 찾았다면 반드시 **그 그룹들의 output 을 나란히 열어 보라.**
건수만 세고 넘어가면 놓치는 것이 있다.
(참고 실측: 완전 중복 20그룹 45건, 그중 output 이 서로 다른 그룹 20개 —
 같은 질문에 `drew.`(3토큰)와 `The past tense of 'draw' is 'drew.'`(12토큰)가
 함께 들어 있다. 지시 튜닝이 가르치는 것은 지식이 아니라 응답 형식의 규약이므로,
 이런 스타일 모순은 13주차 응답 품질에 직접 영향을 준다.)
"문제가 없음을 확인하는 것"도 점검의 정당한 결과다 — 다만 그 결론은
충분히 파고든 뒤에만 말할 수 있다.
```
