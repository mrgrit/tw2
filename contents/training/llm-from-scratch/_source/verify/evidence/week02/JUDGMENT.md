# 발견된 결함

## 결함 #5 — P2-3 통과 기준 "원문 복원"이 원리적으로 불가 (**중대**, 교재-수치오류)

**위치**: Week1-2 교재 2.4절 P2-3 통과 기준

**교재 서술**:
> **📋 실행 프롬프트 P2-3** — 왕복 테스트
> [입력 문장] "It's the last he painted, you know," Mrs. Gisburn said with pardonable pride.
> [할 일] … ③ 원문과 decode 결과가 일치하는지 비교
> **통과 기준:** decode 결과가 원문을 복원할 것.

**실측**:
```
원문   : "It's the last he painted, you know," Mrs. Gisburn said with pardonable pride.
encode : [1, 56, 2, 850, 988, 602, 533, 746, 5, 1126, 596, 5, 1, 67, 7, 38, 851, 1108, 754, 793, 7]
decode : " It' s the last he painted, you know," Mrs. Gisburn said with pardonable pride.
일치    : False
```

encode 결과 ID 21개는 **교재와 완전히 일치**한다(ch02.ipynb code cell #14 저장 출력과 동일).
문제는 decode다. 교재 저장소의 저장된 출력도 동일하게 실패한다:

```
ch02.ipynb code cell #15 저장 출력:
'" It\' s the last he painted, you know," Mrs. Gisburn said with pardonable pride.'
```

**원인 (수학적/구조적)**:
1. 분리 단계에서 `"It's` → `"`, `It`, `'`, `s` 네 토큰이 된다.
2. decode 는 토큰을 **공백으로 이어붙인 뒤**(`" It ' s the …`) 정규식
   `re.sub(r'\s+([,.?!"()\'])', r'\1', text)` 로 **구두점 "앞"의 공백만** 지운다.
3. 따라서 여는 따옴표 `"` **뒤**의 공백과 아포스트로피 `'` **뒤**의 공백은 그대로 남는다.
   → `" It' s`

즉 이 토크나이저의 decode 는 **여는 따옴표와 아포스트로피에 대해 무손실이 아니다.**
"복원된다"는 통과 기준은 교재의 실제 구현과 모순이다.

**분류**: 교재-수치오류. (교재 저자의 원본 구현과 일치하므로 구현 오류가 아니라, 강의교재가
예상 결과를 잘못 적은 것이다.)

**권고 (교재 수정안)** — P2-3을 아래로 교체하면 오히려 교육 효과가 커진다.

```text
**📋 실행 프롬프트 P2-3** — 왕복 테스트

tokenizer_v1.py의 SimpleTokenizerV1로 다음을 테스트해줘:
[입력 문장] "It's the last he painted, you know," Mrs. Gisburn said with pardonable pride.
[할 일] ① encode 결과 ID 리스트 출력 ② 그 ID를 다시 decode한 문자열 출력
       ③ 원문과 decode 결과를 문자 단위로 비교해 다른 위치를 모두 짚을 것
       ④ 차이가 나는 이유를 decode의 정규식과 연결해 설명할 것
[제약] decode 규칙을 고치지 마라. 지금은 한계를 관찰하는 단계다
```

**예상 결과 (정정)**:
```
encode 결과 ID 21개: [1, 56, 2, 850, 988, 602, 533, 746, 5, 1126, 596, 5, 1, 67, 7, 38, 851, 1108, 754, 793, 7]
decode 결과: " It' s the last he painted, you know," Mrs. Gisburn said with pardonable pride.
→ 원문과 두 곳이 다르다: 여는 따옴표 뒤(`" It`)와 아포스트로피 뒤(`It' s`)에 공백이 남는다.
원인: decode는 구두점 "앞"의 공백만 지운다. 여는 따옴표와 아포스트로피는 "뒤"에 붙어야 하는
문자인데 그 규칙이 없다. → 이 토크나이저의 왕복은 무손실이 아니다.
```

**통과 기준 (정정)**: `encode ID 21개가 교재와 일치할 것. decode 는 두 곳(여는 따옴표 뒤,
아포스트로피 뒤)에서 원문과 다르며, 그 이유를 설명할 수 있을 것.`

이 정정은 **2.6절 BPE의 무손실 왕복(V2-3, 5/5 일치)과의 대비를 선명하게** 만든다.
"단순 토크나이저는 왕복조차 무손실이 아니다 → BPE는 무손실이다" 라는 서사가 생긴다.

## 보정 권고 #1 — 한국어 토큰 비율 범위 (경미)

**위치**: Week1-2 교재 2.7절 예상 결과

교재: "한국어는 평균적으로 영어의 수 배(**대략 2~5배**) 토큰을 소모"

실측 (gpt2 BPE, 일상 5쌍 + 보안 5쌍):

| 구분 | 최소 | 최대 | 평균 |
|---|---|---|---|
| 일상 문장 5쌍 | 3.73 | 4.54 | 4.07 |
| 보안 문장 5쌍 | 5.27 | **7.17** | 5.82 |
| 전체 10쌍 | 3.73 | 7.17 | **4.94** |

평균 4.94는 "2~5배" 범위 안이지만, **2배에 가까운 쌍은 하나도 없었고** 보안 용어 문장은
5~7배로 상한을 넘는다. 학생이 6~7배를 보고 "내가 뭘 잘못했나" 의심할 수 있다.

**권고**: "대략 2~5배" → "**대략 4~7배(짧고 한자어가 많은 문장일수록 커진다)**"

근거 자료(P2-9 실측):
- `방화벽이 비정상 트래픽을 차단했다.` → UTF-8 49바이트 / **43토큰** = 토큰당 1.14바이트
- `The firewall blocked abnormal traffic.` → 38바이트 / **6토큰** = 토큰당 6.33바이트
- 43개 토큰 중 **41개가 사람이 읽을 수 없는 바이트 조각**(예: ID 167 = `0xeb`)
