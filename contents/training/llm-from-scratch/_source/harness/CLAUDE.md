# 강의 실습 검증 프로젝트 — 하네스 규칙

## 이 저장소의 목적

『밑바닥부터 만들면서 배우는 LLM』 에이전트 실습 교재(6권, Week 1–15)의 **모든 실행/검증 프롬프트가
실제로 작동하는지, 교재가 제시한 예상 결과·통과 기준과 일치하는지** 전수 검사한다.

나(에이전트)는 두 역할을 번갈아 수행한다.

| 역할 | 하는 일 | 금지 사항 |
|---|---|---|
| **학생(maker)** | 교재의 P프롬프트를 **문면 그대로** 수행한다. 교재에 없는 정보를 보태지 않는다. | 교재가 안 준 힌트로 구현을 보정하는 것 |
| **검사자(checker)** | 산출물을 교재의 예상 결과·통과 기준과 대조해 PASS/FAIL 판정한다. | "거의 같음"으로 넘어가는 것 |

**핵심 원칙: 학생 역할일 때 정답지를 보지 않는다.** 프롬프트만 읽고 구현한 뒤, 그 결과를 정답지와
대조한다. 정답지를 먼저 보고 맞춰 쓰면 "프롬프트가 그 결과를 유도하는가"를 검증할 수 없다.
이 순서를 어기면 검증 자체가 무효다.

## 공통 철칙 (사용자 지시)

1. **순차 실행.** 주차·미션·프롬프트를 병렬로 돌리지 않는다. 한 번에 하나.
2. **자동화 금지.** 전체를 한 번에 돌리는 러너 스크립트를 만들지 않는다. 사람이 실습하듯
   프롬프트 하나씩 수행하고 출력을 눈으로 확인한다. (미션 스크립트 자체는 교재가 요구한
   산출물이므로 작성한다 — 금지 대상은 "검증 과정을 대신 돌리는 메타 러너"다.)
3. **전수 검사.** 표본을 뽑지 않는다. 모든 P/V 프롬프트, 모든 예상 결과 수치를 검사한다.

## 실행 환경 규약

- 실습 코드는 **반드시 `llm-lab` 컨테이너 안에서** 실행한다 (교재 1주차 CLAUDE.md 규칙).
  호스트에 pip 설치 금지.
- 컨테이너 진입: `docker exec -it llm-lab bash`
- 작업 루트(컨테이너 내부): `/work` → 호스트 `/home/mrgrit/llm_from_scratch/work`
- GPU 사용 규약(9주차): ① 모델·배치를 명시적으로 device 이동 ② 시간 측정 전후
  `torch.cuda.synchronize()` ③ 큰 모델은 측정 후 `del` + `empty_cache()`

## 판정 규약

| 판정 | 의미 |
|---|---|
| `PASS` | 교재의 예상 결과와 일치 (수치는 교재가 명시한 자릿수까지) |
| `FAIL` | 불일치. 교재 오류 또는 프롬프트 불충분 → 원인까지 규명해야 종료 |
| `BLOCKED` | 환경 부재로 실행 불가 (예: GitHub Classroom 저장소). 대체 검증으로 우회하고 명시 |
| `GATED` | 호스트를 잠글 수 있어 사람 승인이 필요 (1주차 하드닝). 실행하지 않고 절차만 검증 |

FAIL은 반드시 셋 중 하나로 분류한다:
- `교재-수치오류`: 교재 정답지가 틀렸다
- `교재-프롬프트결함`: 프롬프트가 예상 결과를 유도하지 못한다 (정보 누락/모순)
- `환경차이`: 교재는 맞지만 이 환경(aarch64/CUDA13/최신 라이브러리)에서 값이 달라진다

## 위험 작업 게이트

다음은 **절대 자동 실행하지 않는다.** 절차 검증만 하고 `GATED` 처리한다.
- `PasswordAuthentication no` + sshd 재시작 (P1-2) — 이 호스트는 원격 접속 중일 수 있음
- `ufw enable` (P1-3) — 방화벽 활성화
- 기존 시스템 설정 파일 덮어쓰기

sudo 패스워드는 사용자가 제공했으나, 위 항목에는 쓰지 않는다.
