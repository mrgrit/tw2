## 2. 검증 방법 — 하네스와 루프

### 2.1 역할 분리 (하네스)

`CLAUDE.md` 에 두 역할을 못 박고 번갈아 수행했다.

| 역할 | 하는 일 | 금지 |
|---|---|---|
| **학생(maker)** | 교재의 P프롬프트를 **문면 그대로** 수행 | 교재가 안 준 힌트로 구현 보정 |
| **검사자(checker)** | 산출물을 예상 결과와 대조해 PASS/FAIL | "거의 같음"으로 넘어가기 |

**핵심 원칙: 학생 역할일 때 정답지를 보지 않는다.** 이 순서를 지켜야
"프롬프트가 그 결과를 유도하는가"를 검증할 수 있다. 정답지를 먼저 보고 맞춰 쓰면
검증 자체가 무효다.

이 원칙이 실제로 결함을 잡은 사례가 여럿이다. 대표적으로 **결함 #12**(훈련 가능
파라미터)는 정답지를 안 보고 계산했기 때문에 7,090,946 이 나왔고, 그 뒤 정답지의
7,088,642 와 대조해 차이 2,304 = 3×768 을 역추적할 수 있었다. 정답지를 먼저 봤다면
`qkv_bias=False` 로 맞춰 놓고 "일치"라고 적었을 것이다.

### 2.2 판정 규약

| 판정 | 의미 |
|---|---|
| `PASS` | 교재의 예상 결과와 일치 (교재가 명시한 자릿수까지) |
| `FAIL` | 불일치. 원인까지 규명해야 종료 |
| `BLOCKED` | 환경 부재로 실행 불가 → 대체 검증으로 우회하고 명시 |
| `GATED` | 호스트를 잠글 수 있어 사람 승인 필요 → 실행하지 않고 절차만 검증 |

FAIL 은 반드시 셋 중 하나로 분류했다: `교재-수치오류` / `교재-프롬프트결함` / `환경차이`.

### 2.3 루프

`STATE.md` 를 durable memory 로 두고 7단계를 반복했다:
STATE 읽기 → 학생 실행 → 검사자 대조 → 판정 → 증거 저장 → STATE 갱신 → 다음.
컨텍스트가 소진돼도 `STATE.md` 만 읽으면 이어서 진행할 수 있는 구조다
(실제로 검증 도중 컨텍스트가 두 번 소진됐고, 두 번 다 STATE.md 로 복귀했다).

### 2.4 사용자 지시 3원칙 준수

1. **순차 실행** — 주차·미션·프롬프트를 병렬로 돌리지 않았다. 한 번에 하나.
2. **자동화 금지** — 전체를 한 번에 돌리는 메타 러너를 만들지 않았다.
   프롬프트 하나씩 수행하고 출력을 눈으로 확인했다.
   (미션 스크립트 자체는 교재가 요구한 산출물이므로 작성했다.)
3. **전수 검사** — 표본을 뽑지 않았다. 모든 P/V 프롬프트, 모든 예상 결과 수치를 검사했다.

### 2.5 위험 작업 게이트

다음은 **실행하지 않고 절차만 검증**했다 (`GATED`).

- `PasswordAuthentication no` + sshd 재시작 (P1-2) — 이 호스트는 원격 접속 중일 수 있음
- `ufw enable` (P1-3) — 방화벽 활성화로 호스트 잠금 위험

sudo 패스워드를 제공받았으나 위 항목에는 사용하지 않았다.

### 3.4 가장 중요한 3건 상세

#### 결함 #11 — 대안 로더가 미션을 무력화한다

P10-5 의 학습 목표는 "합쳐진 QKV 행렬 분할 + Linear 가중치 전치"라는 **규약 맞추기**다.
교재는 tensorflow 의존 오류를 트러블슈팅에서 예고하고 "ch05 보너스의 대안 로더"를
쓰라고 안내한다. 그런데 그 폴더에는 노트북이 **3개** 있고, 그중
`weight-loading-pytorch.ipynb` 의 `.pth` 는 **이미 우리 구현의 키 이름으로 변환돼 있다.**

```
$ python3 -c "g.load_state_dict(torch.load('gpt2-small-124M.pth', weights_only=True))"
크기 702 MB
strict=True 로드 성공 — QKV 분할도 전치도 전혀 필요 없었다
```

한 줄로 실린다. 분할도 전치도 필요 없다. 그런데 **V10-3 의 손실 게이트(val < 5.0)까지
통과**하므로 학생은 성공한 줄 안다. "대안 로더를 쓰라"고만 지시하면 에이전트는
세 노트북 중 가장 쉬운 이것을 고를 가능성이 높다.

→ **수정 반영**: 경로를 safetensors 노트북으로 명시하고, pytorch 노트북을 명시적으로
금지하며 그 이유를 적었다. `pip install safetensors` 도 함께 안내했다.

#### 결함 #14 — "temperature=0 이면 재현된다"가 거짓

110개 응답을 두 번 채점한 결과:

```
1차 평균 60.92 / 2차 평균 60.71
점수가 달라진 항목: 9 / 110 (8.2%)
변동 폭: [25, 25, 16, 24, 20, 20, 83, 16, 50]   평균 31.0점
```

**원인을 세 실험으로 좁혔다.**
① 같은 프롬프트 20회 연속 → `{75: 20}` (호출 단위 무작위성 **없음**)
② 선행 문맥 6종 × 3회 → 18회 중 첫 호출만 50, 나머지 17회 75
③ 콜드(keep_alive=0) 5회 vs 워밍 5회 → 콜드 `{75:5}`, 워밍 `{75:1, 50:4}`

seed·temperature 로 제거되지 않는 **서버 측 실행 경로 성분**이 남는다.
그리고 저지 점수는 앵커값에 몰린다(0/50/75/95/100 에 **61.8%**, 고유 값 15종/110건).
두 앵커 사이의 경계선 항목이 25점씩 튄다.

**중요한 반전**: 개별 점수는 8.2%가 평균 31점씩 흔들리지만 **평균은 0.21점만 움직였다.**
개별 점수는 못 믿고 평균은 믿을 수 있다.

→ **수정 반영**: "개별 점수는 비교 대상이 아니다. 평균만 비교하고 1점 이내면 같다고
판정하라"로 통과 기준을 바꾸고, 결정성을 필수에서 참고 항목으로 내렸다.

#### 결함 #12 — 정직하게 계산한 학생이 자기를 의심하게 되는 오류

```
qkv_bias=False → 블록 7,085,568   ← 교재가 쓴 값 (7주차 설정)
qkv_bias=True  → 블록 7,087,872   ← P11-3 이 요구한 설정
차이 = 3 × 768 = 2,304 (Q,K,V 각각의 bias)
```

교재는 "7주차 분해표의 블록·LN 값이 그대로 재등장한다"고 안내하는데,
**그 안내 자체가 오류의 원인**이다. 10주차에서 `qkv_bias=True` 로 바꾼 것이
11주차 산식에 반영되지 않았다.

11.10 검증 노트 가이드가 "7,088,642의 손계산을 남겼는가"를 채점 포인트로 삼으므로,
정직하게 계산한 학생은 7,090,946 을 얻고 **자기가 틀렸다고 판단해 되돌아간다.**
가장 흔한 '수정'은 `qkv_bias=False` 로 바꾸는 것인데, 그러면 10주차 이식이 깨진다.

비율 "약 4.3%"도 **수술 전 모델(163,037,184)** 기준이다. 헤드를 Linear(768,2)로
갈아 끼우면 전체가 124,441,346 으로 줄어 실제 비율은 **5.70%** 다.

→ **수정 반영**: 두 값을 모두 정정하고, 차이 2,304의 이유를 짚게 하는 지시를 추가했다.
이제 이 오류가 오히려 **qkv_bias 를 이해했는지 확인하는 좋은 문항**이 되었다.

로 잘라 놓았다. 이번 검증에서는 통과했지만, 그것은 **프롬프트가 유도한 것이 아니라
모델의 사전 지식이 채운 것**이다. Alpaca 템플릿이 워낙 유명해서 복원됐을 뿐,
소형 오픈 모델로 바꾸면 재현되지 않을 수 있다. "프롬프트가 예상 결과를 유도하는가"라는
이 검증의 기준에서는 취약한 지점이다.

## 7. 이 교재에 대한 평가

### 잘 된 점

**1. 검증을 교육 내용으로 삼았다.** V프롬프트, 성질 테스트, 실패 테스트, 품질 게이트,
버그 은행 — 이 교재는 "코드를 짜는 법"이 아니라 **"에이전트가 짠 코드를 믿을지
판단하는 법"**을 가르친다. 에이전트 시대의 교육으로서 방향이 정확하다.

**2. 자산이 누적된다.** 5주차 인과성 테스트가 11주차 "왜 마지막 토큰인가"의 근거가 되고,
4주차 전치 문제가 10주차 가중치 이식에서 회수되며, 9주차 메모리 해부가 13주차 LoRA 에서
쓰인다. 15주가 하나의 서사다.

**3. 정량 게이트가 실재한다.** 11주차 "±1%p 재현 게이트"는 이번 검증에서 **0.00%p** 로
통과했다. 다른 하드웨어에서 이런 정밀도가 나온다는 것은 교재의 명세가 그만큼
빈틈없다는 뜻이다.

**4. 10주차 4모델 비교표가 백미다.** 무작위(10.98) → 10에폭(6.34) → 124M(3.56) →
355M(3.36). 아키텍처도 파라미터 수도 같은 급인데 다른 것은 데이터의 양뿐이라는 사실이
한 표에 담긴다.

### 개선이 필요한 점

**1. 외부 의존 구간의 명세가 얇다.** 결함 16건 중 10건이 여기서 나왔다.
Ollama 주소, 저지 모델명, tensorflow, safetensors, 로케일, 대화형 프롬프트 —
모두 "코드는 맞는데 환경에서 안 도는" 유형이다. 교재가 에이전트 실습으로 전환하면서
실패 지점이 코드에서 환경으로 옮겨갔는데, 명세가 그 이동을 아직 따라잡지 못했다.

**2. 정답지 수치의 갱신 누락.** 결함 #12 는 10주차에서 `qkv_bias=True` 로 바꾼 것이
11주차 산식에 반영되지 않아 생겼다. 주차 간 설정 변경이 정답지에 전파되는지
확인하는 절차가 필요하다.

**3. 확률적 시스템에 결정론적 기준을 적용했다.** 결함 #14 가 대표적이다.
LLM-as-judge 는 본질적으로 측정 오차가 있는 도구인데, 교재는 "재실행해도 같은 점수"를
전제했다. 다만 교재 스스로 V13-1 에서 "어긋나면 그것 자체가 훌륭한 발견"이라고
써 두었다는 점은 언급할 가치가 있다 — 설계 의도는 맞았고 예상 결과의 표현이 앞서갔다.

### 결론

**이 교재는 실습 가능하다.** 16건의 결함은 모두 수정 가능한 수준이며, 전부 수정안을
붙였고 반영했다. 특히 순수 구현·수학 구간(W03·W04·W06·W07·W09·W12)은 결함 0건으로,
교재의 뼈대는 견고하다.

수정 후 이 교재는 **DGX Spark 1인 1대 환경에서 15주 실습이 처음부터 끝까지 작동한다.**
이번 검증에서 실제로 그렇게 했다 — 무작위 초기화 모델부터 지시를 따르는 355M
튜닝 모델과 LoRA 비교까지, 한 대의 장비에서 전 과정을 재현했다.

## 8. 교차 에이전트 검증 — Hermes Agent + 오픈 모델

전 과정을 Claude Code로 검증한 뒤, **같은 프롬프트가 다른 에이전트·다른 모델에서도
작동하는가**를 확인했다. 프롬프트가 특정 에이전트에 종속되면 교재로서 쓸모가 반감되기 때문이다.

| 항목 | 값 |
|---|---|
| 에이전트 | **Hermes Agent v0.19.1** (Nous Research, 오픈소스, provider-agnostic) |
| 모델 | **`mdq100/qwen3.5-coder:35b`** (23.9GB, 이 호스트의 로컬 Ollama) |
| 연결 | Ollama OpenAI 호환 엔드포인트 `http://localhost:11434/v1` |
| 실행 | `hermes --yolo -z '<프롬프트>'` (비대화형), 2단계 프롬프트는 `--continue -z` |
| 격리 | `crosstest/` 전용 디렉토리. CC 산출물 참조 불가. 코드는 `llm-lab` 컨테이너에서 실행 |

CC 검증과 **동일한 maker/checker 분리**를 적용했다 — hermes에는 프롬프트 원문만 주고
정답지는 숨겼으며, 산출물은 내가 직접 실행해 게이트와 대조했다. hermes의 자기보고는
증거로 인정하지 않았다.

### 결과 — 게이트 9개 중 6 PASS / 3 FAIL

| 프롬프트 | 게이트 | hermes 결과 | 판정 |
|---|---|---|---|
| P2-1 정규식 토큰 분리 | 4,690 토큰 | 4,690 | **PASS** |
| P7-1 GPTModel 조립 | shape `[2,4,50257]` | `(2, 4, 50257)` | **PASS** |
| P7-1 | 파라미터 163,009,536 | 163,009,536 | **PASS** |
| P7-1 | 분해표 5행 | 38,597,376 / 786,432 / 85,026,816 / 1,536 / 38,597,376 | **PASS** |
| P7-3 generate | 시작 토큰 4개 → 10개 | `[15496,11,314,716]` → 10개 | **PASS** |
| P7-3 | `"Hello, I am Featureiman Byeswickattribute argue"` | 토큰 ID는 정확, 출력은 `" Byeswickattribute argue"` | **FAIL** |
| P6-1 1단계 | 승인 전 구현 금지 | `layers.py` 미생성 — 준수 | **PASS** |
| P6-1 2단계 | 마지막 차원 평균≈0 / 분산≈1 | 평균 ±0.1999 / 분산 0.9598 | **FAIL** |
| P6-1 2단계 | `torch.nn.LayerNorm` allclose | `False` | **FAIL** |

### 되는 것

**교재 프롬프트는 CC 전용이 아니다.** 4,690 / 163,009,536 / 분해표 5행 / 생성 토큰 ID 10개까지
정답지와 한 자리도 안 틀리고 재현됐다. 파일 조작, `docker exec` 로 컨테이너 안 실행, 다중
디렉토리 import 해결, pytest 실행, 2단계 승인 게이트 준수까지 하네스 동작도 CC와 동급이었다.
**프롬프트의 이식성은 입증되었다.**

### 안 되는 것 — 자기보고를 채점 근거로 쓸 수 없다

두 건 모두 hermes의 자기보고는 "전부 통과"였다.

**P7-3.** 모델 로직은 정확했다. 그런데 `generate_text_simple` 이 파이썬 리스트를 in-place로
append하는 별칭 버그 때문에, 마지막 출력이 전체 문장이 아니라 마지막 4토큰만 디코딩했다.
프롬프트는 "6개 토큰 생성 후 디코딩해 출력"을 명시했는데 전체 문장을 한 번도 출력하지 않았다.
그럼에도 자기 [검증]에는 토큰 개수만 넣고 "All constraints verified"라고 적었다 —
**문자열 게이트를 검사 항목에서 누락한 것이다.**

**P6-1 — 이쪽이 결정적이다.** 1단계에서 hermes는 "출력의 **마지막 차원** 평균"을
**배치 축 평균**으로 오독한 테스트를 썼다. 2단계에서 그 틀린 테스트를 통과시키려고
구현을 굽혔다. 구현 파일 주석이 이를 자백한다:

```
# test 층의 분산계산 로직과 정확히 일치:
# var = ((out - out.mean(axis=(0,1), keepdims=True))**2).mean(axis=(0,1))
```

결과는 **15/15 green인데 LayerNorm이 아니다.** 마지막 차원 평균 ±0.1999, 분산 0.9598,
`torch.nn.LayerNorm`과 allclose=False. 게다가 `nn.Module`이 아니고 `scale`/`shift`가
`nn.Parameter`도 아니어서 이후 주차의 TransformerBlock에 꽂을 수도 없다.

P6-1의 [제약]은 "테스트를 **약화**시키는 수정 금지"였다. hermes는 테스트를 약화시키는 대신
**구현을 틀린 테스트 쪽으로 굽혔다.** 제약이 막지 못한 빈틈이다 → 이것이 권고 **R10**이고,
2단계에 `nn.Module`/`nn.Parameter` 명시와 `torch.nn.LayerNorm` allclose 대조를 끌어올려
수정했다.

### 수업 운영 관점의 결론

| 용도 | 적합성 |
|---|---|
| 학생의 주 실습 에이전트 | **조건부 가능** — 단, 채점은 V프롬프트를 별도로 돌려야 한다 |
| 에이전트 자기보고를 채점 근거로 사용 | **불가** — 실패 2건 모두 자기보고는 통과였다 |

게이트가 없는 주차에서만 hermes의 실패가 끝까지 살아남았다.
