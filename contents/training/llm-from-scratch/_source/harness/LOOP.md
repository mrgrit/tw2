# 검증 루프 설계 (Loop Engineering)

> "Stop prompting. Design the loop. Get a score."
> 이 검증은 126개 프롬프트 × 약 90개 수치 게이트를 대상으로 한다. 한 번의 긴 프롬프트로는 끝나지
> 않으므로, 상태를 파일에 두고 같은 사이클을 반복하는 루프로 설계한다.

## 루프 1회전 (한 프롬프트당)

```
   ┌─ (1) STATE.md 읽기 → 다음 미검증 프롬프트 1개 선택
   │
   ├─ (2) [학생] 교재의 P프롬프트를 문면 그대로 수행
   │        · 정답지 섹션은 읽지 않는다
   │        · 산출물을 work/weekNN/ 에 실제로 만든다
   │        · 컨테이너 안에서 실행
   │
   ├─ (3) [검사자] ANSWERKEY.md 의 해당 게이트와 대조
   │        · 수치는 교재가 명시한 자릿수까지
   │        · "거의 같음" 금지
   │
   ├─ (4) 판정 PASS / FAIL / BLOCKED / GATED
   │        FAIL → 원인 분류 (교재-수치오류 / 교재-프롬프트결함 / 환경차이)
   │              → 재현 최소 예제를 evidence/ 에 남긴다
   │
   ├─ (5) 증거 기록: verify/evidence/weekNN/<PROMPT_ID>.md
   ├─ (6) STATE.md 갱신 (ledger 한 줄 추가)
   └─ (7) 다음 프롬프트로 → (1)
```

## 종료 조건 (termination)

- 1차 종료: Week01~15의 모든 P/V 프롬프트가 PASS/FAIL/BLOCKED/GATED 중 하나로 확정
- 2차 종료: 모든 FAIL이 교재 수정 또는 원인 규명으로 닫힘
- 3차 종료: hermes agent + open model 교차 검증 완료

## 자율성 레벨 (autonomy level)

| 대상 | 레벨 | 근거 |
|---|---|---|
| 코드 작성·실행·수치 대조 | **L3 무인** | 되돌릴 수 있고 컨테이너 안에 격리됨 |
| 교재 .md 파일 수정 | **L2 보조** | 수정안을 만들고 근거를 제시, 최종 반영은 보고 후 |
| 호스트 시스템 설정 변경 (하드닝) | **L1 보고만** | 잠금(lockout) 위험. 실행하지 않는다 |
| 외부 다운로드 (가중치·데이터셋) | **L3 무인** | 교재가 요구한 공개 리소스 |

## 게이트 (gate)

- **denylist**: `/etc/ssh/*`, `ufw enable`, `systemctl restart ssh`, 기존 홈 디렉토리 파일 삭제
- **allowlist**: `docker` (llm-lab 한정), `pip` (컨테이너 내부), `curl`/`git clone`, work/ 하위 쓰기
- **human gate**: FAIL이 교재 수정을 요구할 때 → 수정안 제시 후 보고

## 실패 모드 대비 (failure modes)

| 실패 모드 | 감지 신호 | 대응 |
|---|---|---|
| 라이브러리 버전 차이로 수치 불일치 | 소수 3자리 이하에서만 차이 | `환경차이`로 분류, 허용 오차 명시 |
| 정답지 자체가 틀림 | 두 가지 독립 방법으로 계산해도 교재와 다름 | `교재-수치오류`, 정정값 산출 |
| 프롬프트가 정답을 유도 못 함 | 프롬프트만 보고 구현했을 때 다른 결과 | `교재-프롬프트결함`, 보강 문구 제안 |
| GPU 비결정성 | 재실행 시 값이 흔들림 | 시드 고정 + 3회 재현 확인 후 판정 |
| 컨텍스트 소진 | 주차 진행 중 대화가 길어짐 | STATE.md 가 스파인 — 읽고 이어서 진행 |
